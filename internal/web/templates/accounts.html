Link a mailbox

Pick where the mailbox lives; one provider opens at a time. Each asks for an alias, which is the name grants and tools refer to the mailbox by. Aliases are never reused, even after unlinking, so an old grant can never end up pointing at a different mailbox.

Gmail A Google account, over OAuth {{if not .GoogleReady}}not configured{{end}}
{{if not .GoogleReady}}
{{template "iconInfo"}}

Google linking is not configured, so Gmail cannot be attached by OAuth here. Set MAILROOM_GOOGLE_CLIENT_ID and MAILROOM_GOOGLE_CLIENT_SECRET from your own Google Cloud project, then restart — or link the same mailbox over IMAP with an app password, which needs no OAuth client at all. See docs/deploying.md.

{{end}}
Microsoft 365 or Outlook.com A work, school or personal Microsoft account, over OAuth {{if not .MicrosoftReady}}not configured{{end}}
{{if .MicrosoftReady}}

One button for both kinds of account: a personal outlook.com, hotmail.com or live.com mailbox and a work or school Microsoft 365 one both consent at the same place. Offline access is among the permissions asked for, which is what returns a refresh token rather than an hour or so of access, and the consent screen is shown every time so that what is being granted is what you just read.

{{else}}
{{template "iconInfo"}}

Microsoft linking is not configured, so a Microsoft 365 or Outlook.com mailbox cannot be attached here. Set MAILROOM_MICROSOFT_CLIENT_ID and MAILROOM_MICROSOFT_CLIENT_SECRET from your own Azure app registration, then restart. See docs/deploying.md.

{{end}}

Microsoft mailboxes read, search, thread, draft, send, label, file, filter and delete through Microsoft Graph. Two things a personal Microsoft account does not have at all are message rules and the automatic-replies setting: those report unsupported_by_provider on such a mailbox and work on a work or school one. This provider has never been run against a live Microsoft account — see docs/providers.md.

Zoho Mail A Zoho account, over OAuth, in its own data centre {{if not .ZohoReady}}not configured{{end}}
{{if .ZohoReady}}

Consent is granted at your account’s own Zoho data centre, and the mailbox is only reachable through that same one — a mailbox in another region cannot be linked here whatever the credentials say. Zoho is asked for offline access with the consent screen forced, which is the only combination that returns a refresh token.

{{else}}
{{template "iconInfo"}}

Zoho linking is not configured, so a Zoho mailbox cannot be attached here. Set MAILROOM_ZOHO_CLIENT_ID and MAILROOM_ZOHO_CLIENT_SECRET from your own Zoho API console, along with MAILROOM_ZOHO_REGION if your account is not in the com data centre, then restart. See docs/deploying.md.

{{end}}

Zoho mailboxes read, send and label. They have no drafts, no filters, no settings and no delete: those tools report unsupported_by_provider rather than failing at the grant. This provider has never been run against a live Zoho account — see docs/providers.md.

Any IMAP server A password or app password, with no OAuth client to register

Any IMAP server, including Gmail with an app password — which is the only way to attach a Gmail mailbox with no OAuth client and no Google Cloud Console. An app password needs 2-Step Verification switched on, and is not your account password.
