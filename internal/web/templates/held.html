{{if .Pending}}

Approving carries the action out now, exactly as it was queued — the client is not asked again and does not get to change it in between. Discarding throws it away; the client is not told, and will find out the way it finds out about anything else, by looking.

Nothing here can happen twice. An action leaves this queue the moment you answer it, so a second press, a resubmitted form or a second tab finds nothing waiting.

{{if .Retention}}

A held send is kept whole while it waits — recipients, body and any attachments, in this server's database and not encrypted. So it does not wait indefinitely: anything still unanswered after {{.Retention}} expires, the message is discarded, and the line naming it stays below. An expired action cannot be approved afterwards. Ask the client to compose it again if it is still wanted.
